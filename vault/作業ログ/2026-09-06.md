# 2026-09-06

「アプリはどこ？」と聞かれた。無かった。公開されていたのは疎通確認ページで、
震度をそのまま表に出していた。作った。→ [[製品の画面]]

## やったこと

**アプリ本体。** `index.html` + `src/app/`。疎通確認は `diagnostics.html` に移した。
震度の数値ではなく結論（平常 / 遅れる / 止まっている見込み / 鉄道は当てにしない）と、
再開までの幅を出す。場所は いまいる場所 / 宿 / 出国便 の 3 つ。

**場所データ。** ODPT から駅の英語名 1,479 件。空港 11 か所は座標を手で書かず
N02 のアクセス駅から取った（ODPT は空港駅を 3 つしか持っていない）。

**オフライン。** Service Worker で同梱データを丸ごと。地震情報だけはキャッシュしない。

**半径を分けた。** 路線は 20km、地点は 5km。宿題に残っていたもの。→ [[設計判断]]

## 直した誤り

**東京駅に長野の中央本線辰野支線が出た。** N02 の中央線に対応づくので、
東京駅の近くに中央線があるだけで拾っていた。系統自身の駅が 5km 以内にあるかで
確かめるようにしたら、湘南新宿ライン・埼京線・副都心線も消えた。どれも東京駅を通らない。

**見出しが 10 時間になった。** 東京駅には東北新幹線も来ている。
判断は最も重い路線、待ち時間の見出しは中央値、と分けた。

**過去の地震を見ると「もう過ぎています」しか出なかった。** 経過時間を引いていたため。
過去表示では引かないようにした。

**Service Worker がコードを更新できなかった。** ビルド工程が無く版が振れないので、
キャッシュ優先だと新しいコードが届かない。ネットワーク優先に変えた。

## 指摘で直した

「宿が『未設定。宿にいるうちに設定してください。』と書かれている。どういう意味？」

現在地から登録する前提だったが、宿を登録するのに宿にいる必要はない。
しかも `いまいる場所` が未設定だと設定画面に登録手段が出ず、行き止まりだった。
設定画面に駅検索を常設した。→ [[製品の画面]]

文言が変なときは、たいてい設計の方が変になっている。

## 直したのに「表示されない」と言われた

配信中のコードには入っていた。ローカルと同一。
**古い Service Worker が居座っていた。**

ネットワーク優先には変えていたが、すでに古い SW が入っている利用者には効かない。
古い SW がコードをキャッシュ優先で返し続けるし、キャッシュ名を据え置いたので
中身も消えなかった。版を上げ、`updateViaCache: 'none'` を付け、
版が変わったら 1 度だけ読み直すようにした。→ [[製品の画面]]

古いキャッシュに偽のコードを仕込んで再現し、消えることを確認した。
**版の上げ忘れが同じ事故を起こす**ので CLAUDE.md に書いた。

**それでも本番では届かなかった。** キャッシュ名は v3 に変わっているのに古いコードが返る。
**ブラウザの HTTP キャッシュ**だった。GitHub Pages が `max-age=600` を返し、
SW の `fetch()` は既定でそこを通る。SW のキャッシュを消しても手前で古いものを掴む。

取得を全部 `cache: 'no-cache'` にした。キャッシュは 2 段ある、というのを見落としていた。

## テストデータを足した

平常時は「平常どおり動いています」しか出ないので、判断部分が確かめられない。
**震度6弱以上は直近の実データに無い**のに、そこが一番判断の重い領域だった。

`test.html` に 2 系統。実際に起きた地震（直近 300 件から震度4以上）と、
想定シナリオ（作り物、震度4〜6強の 5 本）。→ [[動作確認]]

作り物であることは譲らない。赤いテスト表示を画面上部に固定して消せなくし、
テスト表示中は実データを取りに行かない。既定では絶対に出ない。
防災アプリで作り物のスクリーンショットが本物として出回るのが最悪の事故になる。

震度6強で「鉄道は当てにしない / 今夜泊まれる場所を探す。駅で待たないこと。」まで
出ることを確認した。

## デザインを作り直した

「『帰れますか』は分かりにくい。見た目が悪いし、ぱっと見、何がなんだかよくわからない」

そのとおりだった。カードを 3 枚並べただけで、一番大事な「動けるのか、待つのか」が
一言で出ていなかった。画面の一番上もブランド名が占めていた。

名前を **Move or Wait / 動くか、待つか** に。判定そのものを名前にした。
画面は塗りつぶしの判定帯ひとつ + 場所の一覧、に変えた。→ [[製品の画面]]

作り直しの途中で 2 つバグを見つけた。

- CSS のクラス名が衝突していた（`.v-wait` が判定帯の背景と待ち時間の段落の両方に当たる）。
  待ち時間側を `.v-eta` に
- **平常時に場所を設定すると描画が落ちた。** 地震が無いと震度の場が作られないのに、
  場所の行が計算しようとしていた。実データで地震が起きていない今しか出ないバグで、
  テストシナリオでは踏まなかった

判定帯で「見通し不明」がリード文と重複していたのも直した。二度言うと読み飛ばされる。

## 指摘をまとめて直した

7 件。ほとんどが「使ってみたら分からない」種類のもので、こちらの設計の詰めが甘かった。

- **出国便の設定が二段階だった。** タップ →「設定」→ 全部混ざった画面。
  行を開いたらその場所の設定と内訳が同じところに出る形にした
- **設定はダイアログに。** 残したのは言語と共有リンクだけ
- **駅の候補は遅延レーダーに合わせた。** カードを並べず、欄の真下に 1 枚の面
- **4 言語に。** 日本語 / EN / 中文 / 한국어。遅延レーダーと同じ
- **現在地を名前で出す。** 最寄り駅から「新宿 の近く」。行を開けば取り直せる
- **避難場所と地図を足した。** → [[避難場所と地図]]
- **震源も地図に。** 補足なので既定では畳んである

避難場所の出典は国土数値情報 (P20) をやめて国土地理院にした。P20 は最新が
2012 年度で非商用限定。命に関わる案内に 14 年前のデータは使わない。

地図ライブラリは入れずに自前で書いた。CDN から読むと圏外で地図ごと消える。
地震のあとに一番効いてほしい場面で消えるのは本末転倒。

## 訳が無ければ英語、に統一した

日本語以外はすべて英語に寄せる。中文・한국어 の対訳が無いものが多く、
日本語のまま出すより英語の方が読める人が多い、という指示。

- **震源名**は気象庁 bosai の `en_anm` から。一覧に載るのは直近 400 件ほどなので、
  **見かけた対訳は localStorage に貯める。** 使うほど当たるようになる
- 駅名・路線名・空港名も同じ扱い。共有リンクは日本語名しか運ばないので、
  英語名は座標から引き直す

**住所だけは日本語のまま**にした。住所は人に見せて伝えるもので、
現地の表記でないと役に立たない。国土地理院の逆ジオコーディング（鍵なし・CORS 開放）で
「東京都新宿区西新宿一丁目」まで出る。市区町村コードの対応表は同梱した。

## 避難所は「並べる」までにした

「使えることを確認できれば誘導もできる」と聞かれたが、**開設状況は取れない**。
L アラートに集約されているが一般公開の API が無い。→ [[避難場所と地図]]

調べていて、そもそも誘導すべきでないことに気づいた。日本では地震のあと
一斉帰宅を抑制するよう求められている。安全な建物にいるなら、まず動かない。
指定緊急避難場所は「逃げる先」であって「泊まる所」でもない。

一覧より先に「まず動かないこと」を出し、後ろに「開設しているかは分かりません」を置いた。

## タップで表示が変わるのは、こちらの都合が漏れているだけ

「いまいる場所が緯度・経度で、タップすると住所にかわる。違和感がある」

住所を**行を開いたときにしか取りに行っていなかった**。閉じているあいだは
座標のまま、開いた瞬間に住所へ入れ替わる。実装の都合がそのまま画面に出ていた。

位置が決まった時点で取りに行くようにした。閉じたままでも住所が出る。

ついでに、大阪の座標で試したら 大阪府大阪市北区梅田三丁目 まで出た。
ODPT の駅は関東に偏っているが、**逆ジオコーディングは全国効く**。
関西で駅名が引けない場所でも、住所なら出せる。

## ゴールを絞り直した

「このアプリのゴールが分からなくなってきた。何をすればいいんだっけ。
このアプリにしかできないことは何だろう」と聞かれた。

**このアプリにしかできないのは「見込みが立っていません」に数字を与えること**だけ。
震度も運行情報も避難場所も、他が出している。作ってきたものの大半は他でも見られる。

決めるべきことは 1 つ。**待つか、今夜の寝場所を確保するか。**
大地震のあと駅周辺の宿は数時間で埋まるので、1 時間目に決めるか 4 時間目に決めるかで
結果が変わる。→ [[ゴール]]

そこで出し方を変えた。

- **時刻を添えた。** 「51分〜4時間26分」だけだとストレス下で引き算をさせる。
  「09:41〜13:16 ごろ」を並べる
- **「いますること」を決断にした。** 再開の最も遅い見込み + 移動 60 分を終電と比べて、
  「今夜のうちに戻れる見込みです」か「今夜は電車で戻れないかもしれません。
  宿を取るなら早い方がいい」を出す

## 400km 先の揺れで東京が不通になっていた

大阪の想定で東京の宿が「不通」と出るとの指摘。原因は東海道新幹線だった。
東京駅を通るので「この場所の路線」として拾われ、その系統は大阪側で止まる。
**路線の最大震度をそのまま場所の判定に使っていた。** → [[設計判断]]

最も揺れた地点が 50km より遠い路線は、一覧には出すが判定には使わないようにした。
一覧には「京都 付近」と添える。判定が平常なのに不通が並ぶ理由が 1 行で分かる。

直している途中で、**判定が常に平常に倒れる**一歩手前まで行った。
系統の推定が「どこで止まっているか」を返しておらず、距離で絞ると全部落ちる。
系統側にも最大地点を持たせて解決。東京の想定でちゃんと「停止」に戻ることまで
確認してから進めた。片方だけ見て直すと、逆向きに壊れる。

気象庁の観測点と距離、点検区間長、再開までの幅、対応する線路名称。

## 一時滞在施設を入れた

[[ゴール]] に直結する方。電車が動かないと分かった人が次に要るのは、
逃げる先ではなく座って待てる場所。→ [[避難場所と地図]]

**全国では揃わない。** 機械可読で出しているのは東京都（都立 226 件）と
品川区（14 件）だけ。都のデータは住所しか無いので、地理院のジオコーダで
ビルド時に引いて同梱した。226/226 引けた。

**収録範囲の外では「近くに無い」と言わない。** 一番近い施設が 60km より遠ければ
「この地域はまだ収録できていません」と出す。大阪で確認済み。

品川区の CSV で 2 つ壊していた。引用符付きの住所で行がずれ、さらに
`Number('')` が 0 になるので **緯度経度 0,0 が「妥当」として通っていた**。
有限かどうかでは足りない。日本の範囲に収まるかで見るようにした。

路線詳細のレイアウトも直した。`ul.lines li` が `display:flex` のままで、
行と内訳が横に並んで行が潰れ、閉じるボタンが押せなくなっていた。

## 遭遇したときの時系列で追った

「利用想定と実際の動きは合っているか、シミュレーションしてほしい」

コードの挙動を時系列で追ったら、**時間軸の両端で壊れていた**。→ [[シミュレーション]]

- 発生 3 分後（速報段階）: 全地点 unknown → **「平常どおり」と出る**。最悪の誤り
- 余震: 「最新」を取るので、震度4 の余震で本震の判定が**格下げ**される
- 推定の上限を過ぎた後: 行動が「そのまま待つ」のまま

5 か所直した。速報段階を作り、窓の中で最も強い地震を取り、上限を過ぎたら
「再開しているかもしれません」に変え、未設定でも地震の発生を見せ、
間に合わないときはバス・タクシーに触れる。

**テストシナリオは発生 15〜55 分後しか無かった。** 3 分後と 7 時間後を足した。
真ん中だけ見て「動く」と思っていた。

直せていないのは「実際の再開を知る術が無い」こと。ODPT 運行情報の優先度を
上げ直した。見出しに使うためではなく、推定を終わらせるために要る。
