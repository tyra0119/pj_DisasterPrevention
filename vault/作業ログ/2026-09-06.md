# 2026-09-06

「アプリはどこ？」と聞かれた。無かった。公開されていたのは疎通確認ページで、
震度をそのまま表に出していた。作った。→ [[製品の画面]]

## やったこと

**アプリ本体。** `index.html` + `src/app/`。疎通確認は `diagnostics.html` に移した。
震度の数値ではなく結論（平常 / 遅れる / 止まっている見込み / 鉄道は当てにしない）と、
再開までの幅を出す。場所は いまいる場所 / 宿 / 出国便 の 3 つ。

**場所データ。** ODPT から駅の英語名 1,479 件。空港 11 か所は座標を手で書かず
N02 のアクセス駅から取った（ODPT は空港駅を 3 つしか持っていない）。

**オフライン。** Service Worker で同梱データを丸ごと。地震情報だけはキャッシュしない。

**半径を分けた。** 路線は 20km、地点は 5km。宿題に残っていたもの。→ [[設計判断]]

## 直した誤り

**東京駅に長野の中央本線辰野支線が出た。** N02 の中央線に対応づくので、
東京駅の近くに中央線があるだけで拾っていた。系統自身の駅が 5km 以内にあるかで
確かめるようにしたら、湘南新宿ライン・埼京線・副都心線も消えた。どれも東京駅を通らない。

**見出しが 10 時間になった。** 東京駅には東北新幹線も来ている。
判断は最も重い路線、待ち時間の見出しは中央値、と分けた。

**過去の地震を見ると「もう過ぎています」しか出なかった。** 経過時間を引いていたため。
過去表示では引かないようにした。

**Service Worker がコードを更新できなかった。** ビルド工程が無く版が振れないので、
キャッシュ優先だと新しいコードが届かない。ネットワーク優先に変えた。

## 指摘で直した

「宿が『未設定。宿にいるうちに設定してください。』と書かれている。どういう意味？」

現在地から登録する前提だったが、宿を登録するのに宿にいる必要はない。
しかも `いまいる場所` が未設定だと設定画面に登録手段が出ず、行き止まりだった。
設定画面に駅検索を常設した。→ [[製品の画面]]

文言が変なときは、たいてい設計の方が変になっている。

## 直したのに「表示されない」と言われた

配信中のコードには入っていた。ローカルと同一。
**古い Service Worker が居座っていた。**

ネットワーク優先には変えていたが、すでに古い SW が入っている利用者には効かない。
古い SW がコードをキャッシュ優先で返し続けるし、キャッシュ名を据え置いたので
中身も消えなかった。版を上げ、`updateViaCache: 'none'` を付け、
版が変わったら 1 度だけ読み直すようにした。→ [[製品の画面]]

古いキャッシュに偽のコードを仕込んで再現し、消えることを確認した。
**版の上げ忘れが同じ事故を起こす**ので CLAUDE.md に書いた。

**それでも本番では届かなかった。** キャッシュ名は v3 に変わっているのに古いコードが返る。
**ブラウザの HTTP キャッシュ**だった。GitHub Pages が `max-age=600` を返し、
SW の `fetch()` は既定でそこを通る。SW のキャッシュを消しても手前で古いものを掴む。

取得を全部 `cache: 'no-cache'` にした。キャッシュは 2 段ある、というのを見落としていた。

## テストデータを足した

平常時は「平常どおり動いています」しか出ないので、判断部分が確かめられない。
**震度6弱以上は直近の実データに無い**のに、そこが一番判断の重い領域だった。

`test.html` に 2 系統。実際に起きた地震（直近 300 件から震度4以上）と、
想定シナリオ（作り物、震度4〜6強の 5 本）。→ [[動作確認]]

作り物であることは譲らない。赤いテスト表示を画面上部に固定して消せなくし、
テスト表示中は実データを取りに行かない。既定では絶対に出ない。
防災アプリで作り物のスクリーンショットが本物として出回るのが最悪の事故になる。

震度6強で「鉄道は当てにしない / 今夜泊まれる場所を探す。駅で待たないこと。」まで
出ることを確認した。
