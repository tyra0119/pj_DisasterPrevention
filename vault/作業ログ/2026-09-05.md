# 2026-09-05

[[DisasterPrevention]] の着手日。chat から前提を持ち込んで、
震度の空間化 → 路線への割り当てまで通した。

## やったこと

**震度データの空間化。** 最初の山だと見ていたところ。
気象庁の震度観測点一覧表から座標辞書を作り、P2P の `(pref, addr)` で引けるようにした。
実データ 199 イベント / 6,016 観測点で欠落ゼロ。ここは想定より素直に通った。

**路線への割り当て。** 国土数値情報 N02-25 から 596 路線・10,154 駅を取り出し、
線内最大震度を出せるようにした。全国 27,343 地点で 162ms。
総当たりだと 1.2 億回になるので格子索引を入れた。

**GitHub Pages 対応。** リポジトリ直下配信と分かったので、
`src/` の TypeScript をプレーン JS に書き直した（型は JSDoc で保持）。
データを `public/data/` から `data/` に移動。`index.html`（疎通確認ページ）を追加。
ローカルの http-server で実ブラウザ動作を確認、コンソールエラーなし。

## 決めたこと

→ [[設計判断]] に書いた。要点は 3 つ。

- 震度を補間しない
- 報告がないことは欠測ではなく「震度 1 未満」
- 路線は最大値を取る

## 分かったこと

**気象庁 bosai の JSON がそのまま使える。** XML パーサを書く前提が消えた。
英語の震源名まで入っているのは訪日外国人向けとして大きい。→ [[データ源]]

**N02 の路線名は運転系統ではない。** これが次の山になる。→ [[宿題]]

## 詰まったこと

**GitHub Pages に deploy が出ない。**
原因はリモートリポジトリが完全に空だったこと。ローカルもコミット 0 件。
`git ls-remote origin` がブランチを 1 本も返さない状態だった。

加えて、リポジトリが private なら Free プランでは Pages が使えない。
Actions の「pages build and deployment」は Settings → Pages で
Source を設定して初めて現れる。→ [[宿題]]
