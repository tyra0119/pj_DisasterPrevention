# 2026-09-05

[[DisasterPrevention]] の着手日。chat から前提を持ち込んで、
震度の空間化 → 路線への割り当てまで通した。

## やったこと

**震度データの空間化。** 最初の山だと見ていたところ。
気象庁の震度観測点一覧表から座標辞書を作り、P2P の `(pref, addr)` で引けるようにした。
実データ 199 イベント / 6,016 観測点で欠落ゼロ。ここは想定より素直に通った。

**路線への割り当て。** 国土数値情報 N02-25 から 596 路線・10,154 駅を取り出し、
線内最大震度を出せるようにした。全国 27,343 地点で 162ms。
総当たりだと 1.2 億回になるので格子索引を入れた。

**GitHub Pages 対応。** リポジトリ直下配信と分かったので、
`src/` の TypeScript をプレーン JS に書き直した（型は JSDoc で保持）。
データを `public/data/` から `data/` に移動。`index.html`（疎通確認ページ）を追加。
ローカルの http-server で実ブラウザ動作を確認、コンソールエラーなし。

## 決めたこと

→ [[設計判断]] に書いた。要点は 3 つ。

- 震度を補間しない
- 報告がないことは欠測ではなく「震度 1 未満」
- 路線は最大値を取る

## 詰まったこと

**Pages が 404 で、Actions に deploy が出ない。**

最初、ローカルの `origin` が `tyra0119/DisasterPrevention`（空の private リポジトリ）
を向いていたため「何も上がっていない」と誤診した。
実際の公開先は **`tyra0119/pj_DisasterPrevention`**（public）で、
`index.html` / `src/` / `data/` / `.nojekyll` は正しく上がっていた。

本当の原因は **Settings → Pages の Source が「GitHub Actions」になっていること**。
ワークフローファイルが無いので何もデプロイされない。

- `has_pages: true`（Pages は有効）
- `main` ブランチにファイルは揃っている
- `actions/runs` の `total_count: 0`（ビルドが一度も走っていない）
- サイトは 404 "Site not found"

「Deploy from a branch」なら push のたびに *pages build and deployment* が
Actions に出る。それが 0 件ということは branch モードになっていない。

`origin` を `pj_DisasterPrevention` に張り替え、リモートの既存コミット「更新」の上に
周辺ファイル（`scripts/` / `NOTES.md` / `vault/` / `CLAUDE.md` など）をコミットした。
force push は不要だった。
