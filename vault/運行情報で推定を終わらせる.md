# 運行情報で推定を終わらせる

[[シミュレーション]] で一番大きい穴として残ったもの。
「17:00 に再開していても、推定の上限まで『止まっている』と言い続ける」。

## 何で解くか

**鉄道会社の運行情報が「平常」なら、推定を捨てる。** それだけ。

ODPT の `odpt:TrainInformation` が運転系統ごとに文面を持っている。
[[運転系統の対応表]] で系統 ID は揃っているので、そのまま突き合わせられる。

文面は会社ごとに違うが、3 語で分けられる。

| 文面に含まれる語 | 扱い |
|---|---|
| 見合わせ / 運休 / 運転を中止 / 不通 | 止まっている（事実） |
| 遅れ / 遅延 / ダイヤが乱れ | 遅れている |
| 平常 / 通常 | 動いている → **推定を捨てる** |
| どれも無い | 分からない → 推定のまま |

裏が取れた路線には ✓ を付け、内訳に事業者の文面をそのまま載せる。
見込みではなく事実として出せる。

### 語を拾うだけでは足りなかった

実データで 2 つ間違えた。

- 「大雨予報に伴い、運休が発生する**可能性があります**」を「止まっている」と読んだ。
  JR 東日本の全線がそう出ていて、地震も無いのに 91 系統が停止扱いになった
- 「１５分以上の遅延は**ありません**」を「遅れ」と読んだ

**現在形の事実だけを拾う。** 予報・可能性・否定は事実ではない。
読めないものは unknown にして推定を上書きしない。上書きしない方が安全側。
直したら normal 47 / delayed 2 / unknown 91 で、その日の実態と合った。

## 鍵をどこに置くか — 直接に変えた

最初は Cloudflare Worker で中継する設計にした（`proxy/worker.js`）。
だが「主にテストで使うアプリなので、直接アクセスしていい」と決まった。

**鍵はブラウザから直接使う。** `src/app/endpoints.js` の `ODPT_KEYS` に貼る。
公開リポジトリと公開サイトに載るので、誰でも読めて誰でも使える。
それを分かった上での判断。本番で人に配るなら Worker に戻す。

鍵を `.env.local` から自動で写す操作は安全側の仕組みに止められた。
秘密情報を公開リポジトリのファイルへ写すのがちょうど止める対象なので、回避せず、
**貼るのは本人**にした。

ODPT の両エンドポイントは `Access-Control-Allow-Origin: *` で、直接叩ける。

Worker のコードは残してある。

- Worker が鍵を持ち、アプリには鍵抜きの JSON だけ返す
- 応答は 60 秒キャッシュ。同時に 1 万人が開いても ODPT への呼び出しは毎分 2 回
- 返す先はアプリの置き場所（github.io）に絞る
- 無料枠は 1 日 10 万リクエスト

GitHub Pages の外に 1 つ置くことになる。**ビルド無し・サーバ無し**の方針からの
唯一の例外。理由は上のとおりで、これ無しでは推定が終わらない。

## 未設定なら何もしない

`src/app/endpoints.js` の `ODPT_PROXY` が空なら、運行情報は取りに行かない。
アプリは推定だけで動く。中継先を置いたら URL を 1 行書けば繋がる。

**テスト表示中は運行情報を混ぜない。** 作り物の地震に本物の平常運転が乗ると、
全部が「平常」に上書きされて確認にならない。

## 繋いで確かめた

鍵を貼ってもらい、ブラウザから直接 140 系統取れた。分類は Node 側と同じ
normal 47 / delayed 2 / unknown 91。

上書きが効くかは、過去の実地震（8/23 茨城県南部 5弱）を開いて見た。
推定は「停止」、今日の運行情報は「平常」なので、差が出る。

- 京王線・丸ノ内線・都営新宿線・大江戸線・副都心線 → **✓平常**。推定を捨てた
- JR 各線 → 「停止」のまま。JR の文面は雨の予報で unknown、上書きしない

狙いどおり。内訳には「鉄道会社の案内: 平常通り運転しています。」が出る。

ただし**過去の再現に今日の運行情報を混ぜるのは誤り**なので、確認したあとで
テスト表示と同じく除外した。2 週間前の地震に今日の平常運転が乗っても意味がない。

## 繋ぐのに要るもの

`src/app/endpoints.js` の `ODPT_KEYS` に、`.env.local` と同じ値を 2 つ貼って push する。
それだけ。空のままなら運行情報は取らず、推定だけで動く。

`npm run verify:traininfo` で、鍵が通るか・分類が実態に合っているかを Node 側から確かめられる。
