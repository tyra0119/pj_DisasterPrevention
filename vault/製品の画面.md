# 製品の画面

[[DisasterPrevention]] の実体。2026-09-06 に疎通確認ページを置き換えた。
`index.html` + `src/app/`。疎通確認は `diagnostics.html` に移した。

## 名前

**Move or Wait / 動くか、待つか。** 最初は「Can I Get Back? / 帰れますか」だったが、
何のアプリか分からないと指摘された。商品が答える判断そのものを名前にした。
名前だけでは地震や電車の話だと分からないので、一行の説明を添える。

## 画面の作り

**判定帯がひとつ。** 画面を開いて最初に目に入るのが結論。塗りつぶしの色帯で、

- 見出し … 平常どおり / 遅れている見込み / 止まっている見込み / 鉄道は使えない見込み
- なぜそうなのか … 1 行
- 再開まで … 幅で
- いますること … 帯の中の囲み

**その下に場所の一覧。** カードを 3 枚並べるのをやめて、1 行ずつの一覧にした。
左に場所、右に短い印（平常 / 遅れ / 停止 / 不通）。タップで路線の内訳が開く。

**名前は小さく。** 画面の一番上はブランドではなく判定に使う。

**判定の色は明暗テーマで変えない。** 白抜きの塗りなのでどちらでも読める。
緊急時は「いつもと同じ色」であることの方が、テーマへの馴染みより大事。

### 作り直した理由

最初はカードを 3 枚並べただけだった。指摘されたとおり、

- 同じ見た目のカードが並ぶだけで、どこを見ればいいか分からない
- 一番大事な「動けるのか、待つのか」が一言で出ていない。3 枚読んで自分で総合する作り
- 画面の一番上をブランド名とタグラインが占めていて、情報が下に押し出されていた
- 色が淡くて、緊急時に一目で伝わらない

## 何を出すか

**震度の数値を前面に出さない。** 「震度5弱」と言われても、訪日外国人には
それが自分にとって何を意味するか分からない。出すのは結論。

- 平常どおり
- 動いているが遅れる
- 点検のため止まっている見込み
- 鉄道は当てにしない

その下に「再開まで 1時間44分〜5時間35分の見込み」。→ [[停止推定]]

場所は 3 つ。**いまいる場所 / 宿 / 出国便**。前提どおり。
出国便は「出発まで 7時間43分」と並べて、間に合うかを言い切る。
移動時間 2 時間を引いて判断している。

## 設定は右上に集め、行を開いたら路線だけ

2 回変えた。

最初は設定を 1 か所にまとめていた。出国便を押すとさらに「設定」を押す必要があり、
そこに宿の設定まで並んで、何の画面か分からなかった。

そこで行の中に設定を置いた。するとこんどは、**路線を見たいだけなのに設定欄まで
開いて操作しにくい**と言われた。もっともで、地震のあとに毎回見るのは路線の方。

**行を開いたら路線だけ。設定は右上の設定ボタンに全部集める。**
未設定の行を押したときも設定ダイアログが開く。ダイアログは中でスクロールする。
中で操作しても閉じない（宿と便を続けて入れる人が毎回開き直さなくて済む）。

場所ごとの設定（いまいる場所・宿・出国便）は**枠で囲う**。どこからどこまでが
一つの項目か、目で分かるように。言語と共有は枠なしのまま。

「設定つきリンクをコピー」は、押した結果を必ず見せる。コピーできたのか分からないと
二度三度押すことになる。クリップボードが使えない環境では URL そのものを見せる。

## 駅の候補は「読む結果」ではなく「選ぶメニュー」

遅延レーダーに合わせた。カードを並べると 1 件ずつが判定と同じ重さになり、
下の内容を押し出す。**欄の真下に 1 枚の面を浮かせて、罫線で区切る。**
主表記は利用者の言語、副表記にもう一方を小さく添える。

## 現在地は名前で出す

緯度経度を出されても、そこがどこか分からない。最寄り駅を探して
「新宿 の近く」と出す。座標のまま持っておいて、表示名は描画のたびに作る
（言語を切り替えたら名前も変わる）。

行を開けば「現在地を取り直す」がある。再取得の方法が分からない、という指摘への答え。

## 英語を先に置く

読み手は訪日外国人。遅延レーダーと同じ **4 言語（日本語 / EN / 中文 / 한국어）**。
`navigator.languages` で判定し、対応外なら英語。切り替えは設定ダイアログの中。

駅名と震源名は日本語のまま出る。駅は現地の表示と一致している方が使えるので
これでよいが、震源名は読めない。→ [[宿題]]

駅の英語名は ODPT から取った（1,479 駅）。日本語で駅名を打つのは無理なので、
検索は英語でできる必要がある。**現在地取得を主にして、駅検索は代替**にした。
現在地なら言語に関係なく効く。

空港は 11 か所。座標は手で書かず N02 のアクセス駅から取った。
ODPT は空港駅を 3 つしか持っていない（関東の一部事業者しか収録されていない）。

## URL に設定を置く

事前登録は宿・出国便・言語。端末に閉じず URL クエリに入れた。

    ?lang=en&home=35.6812,139.7671&homeName=Tokyo&flight=NRT&dep=2026-09-06T14:30

プッシュ通知を前提にしない代わりに、**リンクを送るのが共有手段**になる。
同行者に「私の設定で見て」と渡せる。

`?event=<id>` で過去の地震を指定して見られる。「あのときどうだったか」を
人に見せるのと、画面の確認に使う。過去を見ているときは経過時間を引かない
（引くと「もう過ぎています」しか出なくなる）。

## 宿は「そこにいるうちに」ではない

最初、宿の未設定時に「未設定。宿にいるうちに設定してください。」と出していた。
現在地から登録する前提だったが、**設計として間違っていた。**

- 宿を登録するのに宿にいる必要はない
- しかも「いつやるか」を説明していて「どうやるか」を言っていない
- `いまいる場所` が未設定だと、設定画面に宿を登録する手段が出ず行き止まりだった

設定画面に駅検索を常設して、いつでも宿を選べるようにした。
文言も「泊まっている場所の近くの駅を検索してください。そこにいる必要はありません。」に。

利用者に指摘されて気づいた。文言が変なときは、たいてい設計の方が変になっている。

## 直した誤り

**東京駅に「中央本線辰野支線」が出た。** 長野の支線。N02 の中央線に対応づくので、
東京駅の近くに中央線があるだけで拾ってしまっていた。
系統自身の駅が 5km 以内にあるかで確かめるようにした。

これで湘南新宿ライン・埼京線・副都心線も東京駅から消えた。どれも東京駅を通らない。
38 路線 → 29 路線。

**見出しが 10 時間になった。** 東京駅には東北新幹線も来ていて、全長の点検で
9〜10 時間と出る。それを見出しにすると、地下鉄で数駅戻るだけの人にまで
「10 時間」と言うことになる。

**判断（待つ/動く）は最も重い路線**、**待ち時間の見出しは中央値**に分けた。
1 本でも止まっていれば経路は崩れるので判断は最悪側でよいが、
時間は代表値でないと使えない。どの路線がどれだけかは一覧で見せる。

## 路線を開くと推定の内訳が出る

**数字を出す以上、どこから来た数字かを見せる。** 「あとどれくらい」がこのアプリの
中身なので、根拠が見えないと使えない。すでに計算しているのに捨てていた情報を出す。

```
線内で最も強い揺れ   震度 5弱 · 東京台東区東上野
                  気象庁の観測点 東京台東区東上野（1.4km）
点検が要る区間      35.7 km
再開まで           1時間4分–4時間55分 · 10:29〜14:20 ごろ
対応する線路        東日本旅客鉄道 山手線 / 東北線 / 東海道線
```

下に「高浜・翠川 (2011) の徒歩点検モデルによる推定。鉄道会社の判断とは別です。」
対応表が全駅を覆えていない系統や、近くの観測が少ない場所では、その旨も添える。

震度の数値は画面の表には出さないが、**内訳では根拠として出す**。
5弱/5強 は日本語圏の書き方なので、英語・韓国語では 5- / 5+ のまま置く。

## オフライン

Service Worker で同梱データを丸ごと置く（gzip 400KB ほど）。
地震のあとは回線が細るので、圏外でも最後に取れた情報で判断できる。

**地震情報はキャッシュしない。** 古い地震を新しい情報として見せる方が、
「取れなかった」と言うより危ない。画面は最終取得時刻を必ず出す。

## 更新が届かない事故

宿の駅検索を出したのに「表示されない」と言われた。配信中のコードには入っていて、
ローカルと同一だった。**古い Service Worker が居座っていた。**

コードをネットワーク優先には変えていたが、それは新しい SW が有効になってからの話で、
すでに古い SW が入っている利用者には届かない。古い SW がコードを
キャッシュ優先で返し続けるし、キャッシュ名（`shell-v1`）を据え置いたので中身も消えない。

3 つ入れて直した。

- **`VERSION` を上げる。** `activate` で古いキャッシュを消すので、これが無効化の要
- **`register(..., { updateViaCache: 'none' })`。** `sw.js` 自体を必ず取りに行く
- **新しい版が有効になったら開いている画面に伝えて 1 度だけ読み直す**
  （`sessionStorage` に印を付けてループを防ぐ）

古いキャッシュに偽のコードを仕込んで再現し、消えることを確認した。

**それでもまだ届かなかった。** キャッシュ名は `v3` に変わっているのに、
返ってくるコードが古いまま。原因は **ブラウザの HTTP キャッシュ**。

GitHub Pages は `Cache-Control: max-age=600` を返す。Service Worker の
`fetch()` は既定でブラウザの HTTP キャッシュを通るので、SW のキャッシュを
消しても、その手前で 10 分前の応答を掴む。

取得を全部 `fetch(request, { cache: 'no-cache' })` にした。
「取得しない」ではなく「必ずサーバに確かめる」なので、
変わっていなければ 304 で済む。`cache.addAll` は cache オプションを取れないので
1 件ずつ `fetch` して `put` する形に変えた。

**キャッシュは 2 段ある。** SW のキャッシュを消しただけでは足りない。

**版を上げ忘れると同じことが起きる。** ビルド工程が無くファイル名に版を振れないので、
`VERSION` が唯一のキャッシュ無効化手段。CLAUDE.md に書いた。

## 残っている穴

**震源名が日本語のまま。** 英語表示でも「茨城県南部」と出る。
気象庁 bosai の JSON は英語の震源名を持っているので、そこから取れる。→ [[データ源]]

**駅検索は関東に偏る。** ODPT の収録範囲がそうなっている。
現在地取得が主なので致命ではないが、関西で駅名検索すると出てこない。
