## 応募の流れ (4 段階)

- [ ] **Step 1** 公共交通オープンデータセンター開発者サイトにユーザ登録 https://developer.odpt.org/
  （確認に最大 2 営業日。既に登録済みなら不要。鍵を 2 つ持っているので済んでいるはず）
- [ ] **Step 2** 開発者サイトにログイン → トップの「公共交通オープンデータチャレンジ2026のエントリーに進む」→ 応募規約を確認して「エントリーする」
  （ボタンが「チャレンジ2026関連情報」に変われば完了。**エントリーするとチャレンジ限定データにアクセスできる**）
- [ ] **Step 3** 作品を公開状態にする（済。GitHub Pages）
- [ ] **Step 4** 10/1 以降、開発者サイトの「関連情報」→「応募方法」のリンクから応募フォームに入力

## 応募条件 (公式「応募条件」より)

- 公共交通オープンデータセンター または GTFS データリポジトリの公共交通オープンデータを利用すること
  → **本作は ODPT の `odpt:Railway` / `odpt:Station` / `odpt:TrainInformation` を利用**（`03_利用データと出典.md`）
- コンテスト期間中、誰でも無償で利用できる状態で公開すること → GitHub Pages で済
- 応募期間中に開発者サイトから提出すること
- **API 利用規約および API 利用ガイドラインを遵守すること** ← 下の「応募前に直すこと」
- 著作権等の権利処理は開発者が保証する（同梱データの出典表示で担保）
- 「日本国内の一般的なインターネット環境で利用可能」なら公開範囲として問題ない (FAQ)
- 一度提出すると説明文・紹介文は編集できない (FAQ)。**フォームの文面は提出前に固める**
- 他コンテストの作品でも、データの利用規約を満たしていれば応募できる (FAQ)

## 審査で見られるもの (公式「審査基準」より)

社会課題解決への寄与 / オープンデータ活用のインパクト / 技術的完成度 / UI・UX の完成度。
`02_作品紹介.md` はこの 4 点に沿って組んである。

## 応募前に直すこと

### 必須

- [ ] **ODPT の鍵をブラウザから外す。** API 利用ガイドラインは「アクセストークンを第三者に開示しない」と定めており、
  いまの `src/app/endpoints.js` は公開リポジトリと公開サイトに鍵を載せている。テスト用途の割り切りだったが、
  応募条件「規約遵守」に真正面から抵触する。
  → `proxy/worker.js` を Cloudflare Workers に置き、`ODPT_PROXY` に URL を入れ、`ODPT_KEYS` を空にする。
  **鍵は再発行する**（既に公開済みの鍵は無効化）。→ vault [[宿題]]
- [ ] `sw.js` の `VERSION` を上げて配信を入れ替える
- [x] 画面のフッターに出典をまとめた。国土地理院・東京都を追加、ODPT はリンク付きで「データを利用しています」の一文を 4 言語で。運行情報の行に生成時刻 (ガイドラインが動的データに求める) を添えた (2026-09-06)
- [ ] 応募フォームの文面 (`01_応募フォーム下書き.md`) を確定する。提出後は直せない

### 推奨

- [x] 紹介動画 1 分 59 秒 (`紹介動画.mp4`、合成音声、11 枚)。詳細版 14 枚は最終プレゼン用。提出前に声を録り直すか原稿を直す → `05_スクリーンショットと動画.md`
- [x] スクリーンショット 10 枚 (`素材/`)。en 6 枚 + ja/zh/ko + 実地震
- [ ] 審査員が「地震が起きていない日」に開いても判定が見えるよう、`?scenario=` の案内を作品説明に入れる（`04_審査員向けデモ手順.md`）
- [ ] README を英語併記にする（訪日外国人向けを謳うなら）
- [ ] 仙台空港線の対応表を手で足す（空港アクセスの穴。→ vault [[宿題]]）
- [ ] 一時滞在施設を東京都以外にも広げるか判断（大阪・京都が空）
